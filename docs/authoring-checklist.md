# Chapter authoring and review checklist

Copyright © 2026 Christopher Snow.

- Start with a practical problem and a question that the source and console can answer. Define new Linux terms before using them.
- Use an editable example and real guest execution. Keep the source, run controls and evidence in reading order.
- Give the learner one concrete change, an optional hint, a worked explanation and a separate transfer task.
- Keep output claims within what the guest demonstrates. Examples using tmpfs cannot demonstrate real crash durability, and emulator timings do not represent physical hardware.
- Preserve drafts when moving between lessons or resetting Linux. Test recovery after interrupted runs and compiler errors.
- Check the built page on a narrow screen and desktop, including both themes, keyboard focus and readable output. Verify the preceding and following lesson around substantive changes.
- Record tested commands, use of relevant skills, any unverified paths, and applicable primary sources.
